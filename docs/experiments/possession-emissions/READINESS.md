# Release decision criteria

This file records criteria before the new emission experiment completes.

1. A replacement must improve natural PFF development Spell F1 by at least 0.020, win at least eight of ten games, and pass the registered class/macro/blind guards.
2. A passing replacement must then pass the old whole-fold and reused-source/sensor guard sets. No relaxed thresholds after results.
3. A changed candidate needs a separately declared untouched confirmation set; the consumed twelve-game final cannot certify it. The six bridges are excluded from this study.
4. If the experiment fails, preserve the already frozen boundary102 candidate and the full negative result. Research complexity alone is not a reason to replace a validated model.
5. Technical release readiness requires exact official-format validation, identical output on repeated clean inference, documented source/label isolation, inspectable weights/dependencies and explicit material weaknesses. Current Linux ARM evidence is a scoped teammate report; it is not independently audited Linux/x86 evidence.
6. Finalist probability cannot be quantified from an external-data score without hidden-match or competitor results. A technical PASS must never be described as qualification assurance.
7. Publication and organizer upload remain on the user's existing hold. Full member identity fields and the requirement for three to five human team members must be resolved before actual submission/eligibility claims.

The aim is a reproducible, defensible submission with measured improvements and known limits. No absolute global-optimality or no-overfitting claim is permitted.
